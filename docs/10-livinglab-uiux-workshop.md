# 온길 리빙랩 UIUX 워크숍 — 로그인 후 화면 디자인 격차 진단·개선안

> 작성 2026-07-18 · 참석: UIUX팀(PM·UIUX전문가·디자이너·퍼블리셔·프론트엔지니어) + 사용자 그룹(당사자·보호자·특수교사·활동지원사·사회복지사·치료사)
> 계기: 사용자 피드백 — "localhost:3000 첫화면 대비 로그인후 대시보드부터 디자인은 너무 세련되지 못하다"

## 0. 개최 배경 및 방식

랜딩페이지(`apps/web/src/app/(public)/page.tsx`)는 그라디언트 히어로·폰 목업·역할별 탭·좌우 교차 기능 하이라이트·다크 보안 섹션 등 마케팅 사이트 수준의 완성도로 설계·구현됐다(`docs/03-uiux.md` §8 참조). 반면 로그인 후 대시보드·업무 화면은 같은 디자인 시스템(§2 색상 토큰, §3 타이포, §4 레이아웃 토큰)을 쓰고 있음에도 실제 적용 밀도가 크게 낮다 — 코드 전수 조사 결과 `accent-amber`/`accent-coral`/`shadow-*`/`gradient` 계열 토큰이 랜딩(파일 2개)에 13회 등장하는 반면, 로그인 후 앱 전체(80여 파일)에는 22회뿐이다. 파일당 밀도로 보면 랜딩이 앱보다 한 자릿수 이상 높다.

이 세션은 실제 코드베이스·디자인 스펙(`docs/03-uiux.md`) 대조 조사를 근거로, PM이 시스템 구조를 시연하고, 6개 사용자 그룹이 실제 화면(계정별 seed 데이터)으로 핸즈온 테스트를 수행한 뒤, UIUX팀이 원인을 진단하고 개선안을 협의하는 형식으로 진행했다.

## 2. PM 시연 요약

1. **랜딩(`/`)** — 그라디언트 히어로, 6도메인 컬러 카드, 역할별 탭, 다크 보안 섹션까지 9개 섹션. "여기서 받은 첫인상이 로그인 직후에도 이어져야 하는데, 다음 화면부터 톤이 갑자기 바뀐다"(PM).
2. **로그인 → 대시보드(guardian, `/dashboard`)** — `PersonSlider` 카드 슬라이더 + 응급정보 카드 + 확인대기 카드. 흰 배경에 `border-2` 테두리만으로 카드를 구분, 그림자·깊이감 없음. 아바타는 이모지(🧑/🧒) 플레이스홀더.
3. **사이드바(`Sidebar`)** — `bg-primary-800` 단색 배경, 아이콘+텍스트 리스트. 랜딩 내비바의 스크롤 전환·backdrop-blur 같은 동적 요소 전무.
4. **글로벌 헤더(`GlobalHeader`)** — `border-b` 한 줄로만 구분된 흰 바. 로고도 텍스트 두 글자(온/길)뿐, 랜딩과 동일한 워드마크이지만 주변 공간감이 없어 훨씬 초라해 보임.
5. **기록 관리(`RecordManager`)** — Split Pane 좌측 리스트가 `border-b border-border` 구분선만 있는 밀도 높은 텍스트 목록. 우측 상세는 `<dl>` 라벨-값 나열(오늘 세션에서 한글 라벨화는 했으나 시각적 스타일링은 그대로).
6. **각 위자드(IEP/ISP/BIP/ITP 등)** — 스텝 인디케이터는 있으나 카드·인풋 스타일이 기본 Tailwind 톤 그대로, 랜딩의 카피라이팅·아이콘 사용 밀도에 비해 건조함.

PM 코멘트: "기능은 이번 세션에서 크게 확장됐지만(BIP·ITP·사례회의록·LEG 등), 시각 완성도는 P0 랜딩 작업 이후 별도로 투자된 적이 없다. 이번이 로그인 후 화면의 첫 정식 UIUX 리뷰다."

## 3. 사용자 그룹 핸즈온 테스트 관찰

### 당사자 (person)
- P-02 자기표현 위자드는 §7-1 스펙(72px 아이콘, 20px+ 폰트)대로 잘 구현돼 대비·크기는 합격. 완료 후 "✨ 저장 애니메이션" 연출은 당초 실제로는 확인 못해 "미구현 의심"으로 남겼으나, Wave UI-4에서 `SaveOverlay.tsx` 코드를 직접 확인한 결과 confetti·bounce·2초 후 자동 리다이렉트까지 이미 완전히 구현돼 있음을 확인 — **오탐, 결함 아님**.
- "다른 화면(대시보드 등)이랑 느낌이 너무 달라서 같은 앱 같지 않다"는 소감(보호자 대신 로그인해 비교 시연).

### 보호자 (guardian)
- PersonSlider 카드: "여러 명 아이를 등록한 부모 입장에서 카드가 다 똑같이 생겨서 빠르게 못 찾겠다 — 아바타가 실제 사진이 아니라 이모지라 더 그렇다."
- 확인대기카드(`PendingConfirmCard`)는 `bg-domain-dai-bg` 컬러가 적용돼 있어 상대적으로 눈에 띄는 편 — "이 카드는 그나마 낫다"는 긍정 피드백. **컬러를 쓴 곳은 잘 보인다는 반증**.
- RecordManager 상세 패널: "정보는 다 보이는데 문서처럼 밋밋하다. 목표/기간 같은 항목은 표나 타임라인처럼 구조가 보였으면."

### 특수교사 (teacher)
- IEP 위자드 6단계: "기능은 좋은데 각 스텝이 다 흰 배경에 검은 글씨라 지금 몇 단계인지 스텝바 숫자를 안 보면 모르겠다."

### 활동지원사 (supporter)
- 일지 5단계 위자드: "현장에서 빠르게 입력해야 하는데 버튼 크기·간격은 터치하기 괜찮다(44px 기준 지켜짐). 다만 강조색이 하나도 없어서 '지금 입력해야 할 것'이 뭔지 시각적으로 안 끌린다."

## 4. UIUX팀 진단 — 근본 원인

**UIUX전문가 + 퍼블리셔 공동 분석:**

1. **깊이감(elevation) 부재** — `docs/03-uiux.md`에 `shadow` 토큰이 아예 정의돼 있지 않다(§4 레이아웃 토큰에 `--br-*`만 있고 shadow 스케일 없음). 랜딩은 큰 섹션 배경색 전환으로 리듬을 만들지만, 앱 내부는 카드가 전부 흰 배경 위 흰 카드라 `border` 한 줄에만 의존 — 설계 문서 자체의 공백.
2. **accent 컬러의 편중된 사용** — `accent-amber`(CTA·마일스톤용)·`accent-coral`(자기표현용)이 랜딩 CTA 버튼에는 적극 쓰이지만, 앱 내부에서는 `PendingConfirmCard` 정도만 도메인 컬러를 배경으로 쓰고 대부분의 액션 버튼·카드가 `primary`/무채색에 머문다. 정보 위계(무엇이 지금 중요한가)를 색으로 못 살리고 있다.
3. **아바타 실체 부재** — `Avatar`/`AvatarImage` 컴포넌트는 이미 존재(`components/ui/avatar.tsx`, GlobalHeader에서 사용 중)하지만 PersonSlider의 카드형 인물 표시는 이모지 하드코딩(`{p.avatarUrl ? "🧑" : ...}` — 실제로는 avatarUrl 유무와 무관하게 항상 이모지만 그림)으로, 실제 프로필 사진 업로드 기능(`avatarUrl` 필드는 스키마에 존재)이 시각적으로 전혀 살지 않는다 — **설계-구현 갭**.
4. **모션·마이크로인터랙션 전무** — 랜딩 내비바는 스크롤 기반 배경 전환(`LandingNavbar`의 `scrolled` 상태)이 있지만, 앱 내부 컴포넌트(Sidebar 접힘/펼침, DropdownMenu 등)는 상태 전환에 트랜지션이 없거나 매우 절제돼 있다.
5. **밀도 대비 여백 부족** — RecordManager/각 위자드의 `<dl>`·목록은 정보 밀도가 높은데 반해 문단 간 여백·구획선 스타일이 랜딩 카드 대비 좁다.

**프론트엔지니어 코멘트:** "위 5가지는 전부 기존 컴포넌트를 갈아엎지 않고 토큰·클래스 레벨에서 점진 개선 가능하다. `Sidebar`/`GlobalHeader`/`PersonSlider`/`RecordContentView`처럼 이미 오늘 세션에서 손댄 파일들도 있어서 회귀 위험은 낮다."

## 5. 토론 및 협의 — 우선순위

- **당사자 모드는 현행 유지가 원칙** — §5 접근성 기준(AAA 목표)이 최우선이라 그림자·모션 같은 장식 요소를 추가하면 오히려 인지 부담이 될 수 있다는 데 전원 합의. 자기표현 완료 애니메이션 "미구현 의심" 건만 별도 확인 항목으로 분리.
- **투자 대상은 보호자·5개 전문가 역할의 대시보드/목록/상세 화면** — 사용 빈도가 가장 높고, 이번 세션에 새로 생긴 화면(BIP/ITP/LEG/사례회의록)까지 포함해 일관되게 적용해야 효과가 크다는 데 합의.
- **디자인 시스템 문서(`docs/03-uiux.md`) 자체에 elevation(그림자) 스케일이 없다는 게 근본 원인** — 컴포넌트를 고치기 전에 토큰부터 정의해야 향후 신규 화면도 같은 문제를 반복하지 않는다는 데 합의(퍼블리셔 강력 주장, 전원 동의).
- 사회복지사가 제기한 "ISP 달성률 바 실제 구현 방식" 확인은 우선순위 낮음(시각적 하자가 아니라 확인 사항)으로 분류, Wave 착수 전 5분 내 코드 확인으로 해소(→ 이미 진행바 컴포넌트로 구현돼 있음을 확인, 문제 없음).

## 6. 개선안 — Wave 구성

### Wave UI-1: 디자인 토큰 보강 (선행, 필수) — ✅ 완료(2026-07-18)
`docs/03-uiux.md` §4-1에 **elevation(그림자) 스케일** 신설 완료.

| 클래스 | 용도 |
|--------|------|
| `shadow-sm` | 리스트 아이템, 인풋 포커스 |
| `shadow-md` | 카드(PersonSlider, RecordManager 패널, 위자드 카드) |
| `shadow-lg` | 드롭다운/팝오버(오늘 신설한 DropdownMenu 등), 모달 |

퍼블리셔 검토 결과 별도 CSS 변수(`--shadow-*`) 신설 없이 Tailwind v4 기본 `shadow-sm`/`md`/`lg` 유틸리티에 용도를 명문화하는 방식을 채택했다 — `AuthCard`가 이미 `shadow-sm`을 쓰고 있어(`components/auth/AuthShell.tsx`) 신규 도입 비용이 없고, 새 CSS 변수 스케일을 따로 유지보수할 필요도 없다. 원칙: 흰 배경 위 흰 카드는 `border` 단독이 아니라 반드시 `shadow-sm` 이상을 함께 준다. 당사자 모드는 §5 접근성 원칙(WCAG AAA)에 따라 이 스케일 적용 대상에서 제외.

### Wave UI-2: 핵심 컴포넌트 리터치 — ✅ 완료(2026-07-18)
- `PersonSlider` 카드: `shadow-md` 적용 + 실제 `Avatar`/`AvatarImage`/`AvatarFallback` 컴포넌트로 교체(이모지는 avatarUrl 없을 때만 폴백) + 응급정보 카드·요약 3카드(`Card` 헬퍼)·슬라이더 화살표 버튼까지 동일 elevation 원칙 적용.
- `GlobalHeader`/`Sidebar`: 헤더에 `shadow-sm` 추가(+`relative z-10`으로 아래 콘텐츠 위에 뜨도록). 사이드바는 활성 메뉴 항목에 좌측 accent 바(StageBadge의 "좌측 4px 색상 바" 패턴 재사용) — **부수 발견**: `layout.tsx`(Server Component)가 pathname을 몰라 `SidebarItem.active`를 한 번도 채워준 적이 없어 활성 강조가 애초에 동작한 적이 없었다. `Sidebar`가 `usePathname()`으로 직접 판정하도록 재구성해 근본 해결.
- `RecordContentView`(웹): 배열 아이템 카드에 `shadow-sm` + 여백 확대(`gap-2`→`gap-3`, `p-2.5`→`p-3`), 필드 간 여백도 확대. 모바일 버전은 React Native의 플랫폼별 그림자 속성(`shadowColor`/`elevation`)이 에뮬레이터 없이는 검증 불가해 이번 Wave에서 보류.
- `PendingConfirmCard` 패턴 확대 적용 중 **부수 발견**: 대시보드 "알림" 카드가 "알림 시스템 준비 중"이라는 stale 문구를 하드코딩하고 있었다(오늘 세션 초반에 실제 알림함(`/notifications`)을 이미 구현했는데 이 카드만 갱신이 안 됨) — `/notifications` 링크로 교체.

### Wave UI-3: 정보 위계용 accent 컬러 확대 적용 — ✅ 완료(2026-07-18)
- 역할별 Home CTA 재조사 결과 **보호자(guardian) 대시보드만 예외**였다 — supporter/teacher/social_worker/therapist/person 5개 역할은 이미 전부 `accent-amber` 주 CTA를 쓰고 있었음(선행 라운드에서 이미 적용된 상태). `dashboard/page.tsx`의 "+ 당사자 추가"/"당사자 등록하기" 버튼만 기본 primary 초록이던 것을 `accent-amber`로 통일.
- 평가보고서 3열 비교 뷰(`EvalComparisonTable.tsx`)의 증감 셀을 텍스트 색상만 쓰던 것에서 배경 칩(pill)으로 승격 — 증가는 `bg-domain-med-bg`(도메인 accent 톤), 감소는 별도 경고색(`bg-red-50`, accent와 혼동 방지), 변화없음은 중립 `bg-muted`. 표를 스캔할 때 놓치기 쉽다는 치료사 피드백(§3)을 직접 반영.

### Wave UI-4: 모션 보강 (선택, 저위험 우선) — ✅ 완료(2026-07-18)
- Sidebar 접힘/펼침(`transition-[width]`)·DropdownMenu 열림/닫힘(`data-open:animate-in` 등)은 이미 Tailwind v4 기본 duration(150ms)을 쓰고 있어 추가 조정 불필요했음을 확인. 실제 갭은 **`prefers-reduced-motion` 전역 처리가 아예 없었다는 것** — `globals.css`에 `@media (prefers-reduced-motion: reduce)` 규칙을 신설해 모든 `animation`/`transition` 유틸리티에 일괄 적용(컴포넌트별 개별 처리 대신 전역 1곳, 신규 컴포넌트도 자동 적용).
- 자기표현(P-02) 완료 애니메이션은 **확인 결과 이미 완전히 구현돼 있었다** — `SaveOverlay.tsx`(confetti 이모지·bounce·2초 후 자동 리다이렉트, 프로토타입 web-person.html 재현이라는 주석까지 존재). §3 당사자 관찰 항목의 "미구현 의심"은 **오탐으로 정정**한다.

### 범위 밖(당사자 모드)
접근성 우선 원칙에 따라 P-01/P-02는 시각 리터치(Wave UI-1~3) 대상에서 제외. 다만 전역 reduced-motion 규칙은 당사자 모드에도 동일하게 적용된다(모션 민감 사용자 보호는 모드 구분 없이 항상 유효한 접근성 요건이므로).
