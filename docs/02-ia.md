> **모바일 열 갱신(2026-07-22)**: 기존 "미상(파일 수 44)"는 갱신되지 않은 채 여러 라운드 동안 방치돼 있었다 — 실제로는 `apps/mobile/src/screens`가 이미 57개 파일(2026-07-19 Wave P-4 하단 탭바 도입 시점의 `PersonPickerScreen`·`RoleSettingsScreen` 등 공용 화면 신설 포함)로 늘어나 있었다. `apps/mobile/src/navigation/types.ts`의 7개 StackParamList·6개 TabParamList를 근거로 role별 목록을 §3-11에 신설했다. 웹과 달리 모바일은 URL이 없어 화면 ID 대신 스크린 컴포넌트명·네비게이션 라우트명을 기준으로 정리했다.

> G-21(기록 작성·수정)은 최초 IA 설계 이후 보호자 기록 직접 작성 권한 반영을 위해 추가된 화면이다(§3-3, PRD §5-3 F-G-04). G-22(대리 자기표현 작성)는 2026-07-17 SELF-001 대리 작성 신설(`createSelfExpressionForPerson`) 반영 화면이다.

> ⚠️ **정정 이력(2026-07-17 갭 분석):** 기존 "웹 88 / 모바일 81"이라는 합계는 근거를 추적할 수 없어(문서 최초 작성 시점부터 세부 항목 나열 없이 총계만 기재됐던 것으로 추정) **폐기**하고, `§3-2~3-8`에 실제 나열된 화면 ID를 role별로 직접 센 값으로 교체했다. A-11(소셜 OAuth 콜백, 무화면 Route Handler)은 라우트 자체가 아직 없다(설계만 확정된 미구현 상태, P3-7 OAuth 갭과 일치) — 화면은 아니지만 §3-2 표에는 ID로 남아있어 아래 정정에서는 표 포함 카운트로 통일했다. **모바일은 이 문서에 role별 화면 ID 목록 자체가 없어** role별 재구성이 불가능하다 — `apps/mobile/src/screens`의 실제 파일 수(44개)만 참고치로 남기며, role별 목록화는 후속 작업이 필요하다.
>
> **전면 재검증(2026-07-18, qa-verifier 전체 문서 정합성 검토)**: 2026-07-17까지의 정정 이후에도 G-22(대리 자기표현)·W-22/W-23(사례회의록)·T-19(ITP) 4건이 §3-2~3-8 표에는 반영됐지만 위 요약표 role별 행이 갱신되지 않아 다시 어긋나 있었다(특수교사 6→실제 9, 사회복지사 8→실제 11 등). `§3-2~3-8`을 라인 범위별로 다시 전수 카운트해 위 표를 **57개**로 갱신했다 — 총계만 손대고 역할별 행을 놓치는 동일 실수가 반복되지 않도록, 이번엔 역할별 행과 합계를 함께 재확인했다.
>
> **재정정(2026-07-22, 종합 갭 분석)**: 2026-07-18 이후 세션에서 신설된 화면 4개가 이번에도 §3-2~3-8 표에 반영되지 않고 있었다 — `/notifications`(알림함, Wave M-1/2026-07-18 신설), `/settings/profile`(프로필 수정, 2026-07-20 신설), `/journals/:id/edit`(임시저장 일지 이어작성, 2026-07-21 신설), `/dashboard/persons/:id/edit`(당사자 정보 수정, 2026-07-19 신설). A-12·A-13·G-03·S-14로 신규 ID를 부여하고 합계를 **61개**로 갱신했다.
>
> **랜딩 지원 페이지 신설(2026-07-31)**: 랜딩 푸터 "지원" 섹션의 이용 안내·자주 묻는 질문·문의하기 3개 링크가 더미 상태였던 것을 정적 페이지로 구현하며 A-14·A-15·A-16을 부여했다. 공통 행 14→17, 합계 **64개**로 갱신(역할별 행과 합계를 함께 갱신하는 기존 원칙 유지).
