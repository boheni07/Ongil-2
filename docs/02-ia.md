## 2. 화면 유형 정의 (Screen Types)

| 코드 | 유형 | 설명 | 대표 화면 |
|------|------|------|---------|
| ST-01 | Hub / Dashboard | 요약 카드 + 빠른 진입점 | G-01, S-01, W-01 |
| ST-02 | List | 목록 + 필터/검색 | 기록 목록, 알림 목록 |
| ST-03 | Detail | 상세 읽기 전용 | 기록 상세, 인계인수 상세 |
| ST-04 | Form — Single | 단일 페이지 폼 | 관찰기록, 회기일지 |
| ST-05 | Form — Multi-step | 단계 분할 위자드 | IEP(6단계), 일지(5단계), 권한(4단계) |
| ST-06 | Timeline | 시간순 피드 + 도메인 레인 | G-10, T-20, W-20, TH-20 |
| ST-07 | Matrix / Table | 행·열 표 + 인라인 필터 | 권한 매트릭스, 접근 로그 |
| ST-08 | Icon Selector | 대형 아이콘 선택 (72×72px) | 당사자 자기표현 P-02 |
| ST-09 | Auth / Onboarding | 인증·역할 선택·최초 설정 | 로그인, 회원가입 |
| ST-10 | Modal / Bottom Sheet | 오버레이 확인·간단 입력 | 삭제 확인, 날짜 선택 |
| ST-11 | Settings | 설정 항목 + 토글 | 알림 설정, 접근성 |

### 3-1. 화면 수 요약

| 역할 | 웹 (검증됨, 2026-07-18) | 모바일 |
|------|:--:|:------:|
| 공통(인증+랜딩) | 12 |<!-- A-11 소셜 콜백은 무화면 Route Handler지만 표에는 포함, 아래 각주 참조 --> 미상 |

| 치료사 (Therapist) | 6 | 미상 |
| **합계** | **57** | **미상(파일 수 44)** |

> G-21(기록 작성·수정)은 최초 IA 설계 이후 보호자 기록 직접 작성 권한 반영을 위해 추가된 화면이다(§3-3, PRD §5-3 F-G-04). G-22(대리 자기표현 작성)는 2026-07-17 SELF-001 대리 작성 신설(`createSelfExpressionForPerson`) 반영 화면이다.

> ⚠️ **정정 이력(2026-07-17 갭 분석):** 기존 "웹 88 / 모바일 81"이라는 합계는 근거를 추적할 수 없어(문서 최초 작성 시점부터 세부 항목 나열 없이 총계만 기재됐던 것으로 추정) **폐기**하고, `§3-2~3-8`에 실제 나열된 화면 ID를 role별로 직접 센 값으로 교체했다. A-11(소셜 OAuth 콜백, 무화면 Route Handler)은 라우트 자체가 아직 없다(설계만 확정된 미구현 상태, P3-7 OAuth 갭과 일치) — 화면은 아니지만 §3-2 표에는 ID로 남아있어 아래 정정에서는 표 포함 카운트로 통일했다. **모바일은 이 문서에 role별 화면 ID 목록 자체가 없어** role별 재구성이 불가능하다 — `apps/mobile/src/screens`의 실제 파일 수(44개)만 참고치로 남기며, role별 목록화는 후속 작업이 필요하다.
>
> **전면 재검증(2026-07-18, qa-verifier 전체 문서 정합성 검토)**: 2026-07-17까지의 정정 이후에도 G-22(대리 자기표현)·W-22/W-23(사례회의록)·T-19(ITP) 4건이 §3-2~3-8 표에는 반영됐지만 위 요약표 role별 행이 갱신되지 않아 다시 어긋나 있었다(특수교사 6→실제 9, 사회복지사 8→실제 11 등). `§3-2~3-8`을 라인 범위별로 다시 전수 카운트해 위 표를 **57개**로 갱신했다 — 총계만 손대고 역할별 행을 놓치는 동일 실수가 반복되지 않도록, 이번엔 역할별 행과 합계를 함께 재확인했다.

### 3-10. 기록 확인(Confirmation) 배지·화면 적용 지점

"승인"이 아니라 "확인" 절차(PRD §3-4, ERD §4-6)가 노출되는 화면 목록. 컴포넌트 사양은 `03-uiux.md` §6-7 `ConfirmBadge` 참조.

| 화면 ID | 화면명 | 적용 방식 |
|--------|--------|---------|
| G-01 | 대시보드 | "확인 대기 기록 N건" 요약 카드 신규 (기존 최근기록/권한현황/알림 카드 옆) |
| G-20 | 기록 관리 목록 | 확인 대기 항목에 `ConfirmBadge`(미확인) 칩 표시, 목록 정렬 시 미확인 우선 |
| G-20D | 기록 상세 | `requires_confirmation=true`이면 상단에 "확인했습니다" CTA 노출, 확인 후 확인자·확인일시 표시로 전환 |
| P-10 | 기록 보기 (당사자) | 성년기(`adult`)에 한해 본인이 확인 주체 — 쉬운 언어로 "이 기록을 봤어요" CTA |
| T-13, W-13, TH-13 | 각 위자드 6/6·5/6·5/6 확인 단계 | 제출 시 "확인 요청 대상: {보호자명 또는 본인}" 안내 문구 추가 |
