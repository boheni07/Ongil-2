## 1. 플랫폼 개요

### 1-1. 플랫폼 정의

**온길**은 장애인의 생애주기(의료·교육·복지·일상·전환·법률) 기록을 당사자 중심으로 관리하는 다역할 협업 플랫폼이다.

| 항목 | 내용 |
|------|------|
| 핵심 철학 | 당사자 중심 — 모든 기록의 주인은 당사자, 이해관계자는 허락받은 범위만 접근 |
| 지원 역할 | 당사자(Person) · 보호자(Guardian) · 활동지원사(Supporter) · 특수교사(Teacher) · 사회복지사(Social Worker) · 치료사(Therapist) |
| 기록 도메인 | 의료(MED) · 교육(EDU) · 복지(WEL) · 일상(DAI) · 전환(TRA) · 법률(LEG) |
| 플랫폼 | 반응형 웹 (Next.js) + 모바일 앱 (React Native/Expo) |
| 보안 | Supabase PostgreSQL + RLS 행 수준 보안 · PIPA §22-24 준수 |

### 1-2. 브랜드 정체성

**마스터 슬로건:** "내 삶의 모든 길이 여기 있습니다"

**온길**이라는 이름의 세 겹 의미:
- 온(溫, 따뜻함) — 온기 있는 기록
- 온(全, 전체) — 생애 전체의 연속성
- 길(道) — 삶의 여정

### 1-3. 6개 생애주기 도메인

| 코드 | 도메인 | 색상 | 주요 기록 유형 |
|------|--------|------|--------------|
| MED | 의료·건강 | `#E04545` | 진단, 처방, 재활계획, 치료계획서, 회기일지, 평가보고서 |
| EDU | 교육 | `#4377C0` | IEP, 수업일지, 관찰기록, 전환교육계획, 가정통신 |
| WEL | 복지서비스 | `#3EA673` | ISP, 서비스 이용계획, 전환계획, 서비스 현황 |
| DAI | 일상·돌봄 | `#E8991E` | 활동지원 일지, 식사/건강 체크, 행동 관찰 |
| TRA | 성인전환 | `#8A5DC6` | 진로탐색, 자립생활계획, 직업훈련 기록 |
| LEG | 법률·권리 | `#5A7FA0` | 후견 기록, 권익옹호, 법적 지원 현황 |

## 2. 전체 IA 구성도

### 2-1. 플랫폼 전체 맵

```
온길 플랫폼
│
├── [PUBLIC] 랜딩페이지 (/)
│   ├── Hero — 핵심 메시지 + CTA
│   ├── 신뢰 지표 — 통계 숫자
│   ├── 플랫폼 소개 — 온길이란?
│   ├── 6개 도메인 — 생애주기 기록
│   ├── 역할별 서비스 — 6개 역할 탭
│   ├── 주요 기능 하이라이트
│   ├── 보안·개인정보 신뢰
│   ├── 이용 절차 3단계
│   └── 최종 CTA
│
├── [AUTH] 인증 공통 (/login, /signup, /invite, /reset-password)
│   ├── 로그인
│   ├── 회원가입 → 역할 선택 → 기본정보 → 동의수집 → 이메일인증
│   ├── 초대 링크 수락
│   └── 비밀번호 재설정
│
├── [APP-WEB] 대시보드 앱 (인증 후)
│   ├── 당사자 전용 (/ → /home, /records, /settings)
│   ├── 보호자 (/dashboard, /persons/:id/*)
│   ├── 활동지원사 (/home, /journals, /handovers)
│   ├── 특수교사 (/home, /records/iep, /records/observation, /timeline)
│   ├── 사회복지사 (/home, /records/isp, /records/transition, /timeline)
│   └── 치료사 (/home, /records/therapy-plan, /records/session, /timeline)
│
└── [APP-MOBILE] 모바일 앱
    ├── 당사자 전용 앱 (3탭 간소화 UI)
    ├── 보호자 (5탭: 홈·타임라인·기록·권한·설정)
    ├── 활동지원사 (4탭: 홈·일지·인계인수·설정)
    ├── 특수교사 (5탭: 홈·IEP·관찰·타임라인·설정)
    ├── 사회복지사 (5탭: 홈·ISP·전환·타임라인·설정)
    └── 치료사 (5탭: 홈·치료계획·회기일지·평가·설정)
```

### 2-2. 스크린 유형 정의 (ST)

| 코드 | 유형 | 설명 | 대표 화면 |
|------|------|------|---------|
| ST-01 | Hub / Dashboard | 요약 카드 + 빠른 진입점 | 보호자 대시보드, 각 역할 홈 |
| ST-02 | List | 아이템 목록 + 필터/검색 | 기록 목록, 알림 목록 |
| ST-03 | Detail | 단일 아이템 읽기 전용 상세 | 기록 상세, 인계인수 상세 |
| ST-04 | Form — Single | 단일 페이지 입력 폼 | 관찰기록 작성, 회기일지 작성 |
| ST-05 | Form — Multi-step | 단계 분할 위자드 | IEP 작성(6단계), 일지(5단계), 권한부여(4단계) |
| ST-06 | Timeline | 시간순 피드 + 도메인 레인 뷰 | 생애주기 타임라인 |
| ST-07 | Matrix / Table | 행·열 표 구조 + 인라인 필터 | 권한 매트릭스, 접근 로그 |
| ST-08 | Icon Selector | 대형 이미지 아이콘 선택 | 당사자 자기표현 4단계 |
| ST-09 | Auth / Onboarding | 인증·역할 선택·최초 설정 | 로그인, 회원가입 |
| ST-10 | Modal / Bottom Sheet | 오버레이 확인·간단 입력 | 삭제 확인, 날짜 선택 |
| ST-11 | Settings | 설정 항목 목록 + 토글 | 알림 설정, 접근성 설정 |

## 5. 역할별 UIUX 설계

### 5-1. 당사자 (Person) — 접근성 최우선

**멘탈 모델:** 폰 쉘(Phone Shell) 패러다임. 기기 전체가 당사자의 것.

**핵심 원칙:**
- 아이콘 크기 72×72px (터치 영역 56×56px 이상)
- 글자 크기 20px+, 고대비 모드 지원 (WCAG AAA 목표)
- 1화면 = 1질문 원칙

| Step | 내용 |

### 8-2. 모노레포 구조

```
OnGil-Harness/
├── apps/
│   ├── web/              ← Next.js App Router
│   └── mobile/           ← React Native (Expo)
├── packages/
│   ├── shared/           ← API 클라이언트, 타입, 유틸
│   └── validation/       ← Zod 스키마 (웹·모바일 공유)
├── supabase/
│   ├── migrations/       ← Prisma 마이그레이션
│   └── functions/        ← Edge Functions (알림·cron)
└── Basic-Doc/            ← 도메인 문서
```

### 8-3. 보안 아키텍처

```
[클라이언트]
    ↓ HTTPS
[Supabase Auth] ← JWT 발급
    ↓
[PostgreSQL + RLS]
    │ 모든 쿼리는 auth.uid() 기반 RLS 정책 통과
    │ permissions 테이블 JOIN으로 도메인별 접근 제어
    ↓
[Supabase Storage]
    └── Presigned URL (만료 시간 제한)
```

**RLS 핵심 정책:**
- `persons`: 본인(당사자) 또는 주보호자만 SELECT
- `records`: permissions 테이블에서 `is_active=true` + `valid_until` 유효 + 해당 domain 권한 확인
- `permissions`: 주보호자만 INSERT/UPDATE/DELETE
- `permission_logs`: INSERT만 허용 (변경 이력 불변)
